## 1. Вариант 15 — что именно мы автоматизируем

### 1.1 Формулировка предметной области

> Закреплена в материалах ЛР1/ЛР2 этого репозитория (восстановлена по заданию варианта; самого списка вариантов в методичках нет — если в ведомости у тебя другой текст/номер, правим этот раздел и всё, что от него зависит).

1. В университете учатся **студенты**.
2. **Выпускающее подразделение** разрабатывает **учебный план** образовательной программы: перечень дисциплин, для каждой — **вид аттестации** (зачёт, экзамен, зачёт с оценкой, курсовая работа, государственная аттестация), **семестр** и **кафедра-исполнитель**.
3. Учебные планы **проверяются АНОК** (автономная некоммерческая организация / центр аккредитации и нормативно-методического контроля) на **соответствие требованиям ФГОС**.
4. План **подписывают**: руководитель выпускающего подразделения, начальник АНОК, проректор по учебной работе.
5. На **учёном совете** планы **утверждаются** и **подписываются ректором**; утверждение происходит **ежегодно**.
6. До начала семестра в план можно внести **изменения** — они оформляются **служебными записками**, которые подписывают руководители **выпускающего** и **реализующего** подразделений.
7. **АНОК вносит изменения** в план и **повторно** проверяет его на соответствие ФГОС.

### 1.3 UML-диаграмма (`UML(4)-ДК.drawio.pdf`) → объекты 1С → лабораторные

Диаграмма классов — это не только структура (ЛР1–ЛР2), но и **требования к коду** (ЛР4–ЛР5). Методы классов мы обязаны «приземлить» на платформенные механизмы:

| Класс UML и его методы | Объект конфигурации | Где реализуем |
|---|---|---|
| `Пользователь` (логин, пароль, роль), `авторизоваться()`, `выйти()` | Справочник `Сотрудники` + Перечисление `РолиПользователей` | ЛР2 (данные) · ЛР3 (роль в форме) · роли/интерфейсы — вне обязательного задания (по желанию) |
| `УчебныйПлан`: `статус`, `датаСоздания`, `датаУтверждения`, `списокДисциплин`, `изменитьСтатус()` | Документ `УчебныйПлан`, ТЧ `Дисциплины`, регистр сведений `ИсторияСтатусовУчебныхПланов` | ЛР2 · **ЛР5** (`ОбработкаПроведения` → менеджер записи в регистр) |
| `Дисциплина`: `семестр`, `часы`, `зет`, `формаАттестации` | Справочник `Дисциплины` (каталог) + колонки ТЧ `Дисциплины` плана | ЛР2 · **ЛР4** (пересчёт ЗЕТ↔часы) · **ЛР6** (загрузка из Excel) |
| `СлужебнаяЗаписка`: `ТипИзменения`, `статус`, `связанныйПлан`, `создать()`, `изменитьСтатус()` | Документ `СлужебнаяЗаписка` + ТЧ `Изменения` + Перечисление `СтатусыСлужебнойЗаписки` | ЛР2 · **ЛР4** (кнопка «Отправить в АНОК») · **ЛР5** (корректирующие движения) |
| `Кафедра` (название, институт) | Справочник `Подразделения` (Тип = Кафедра) | ЛР2 · **ЛР5** (`ПередЗаписью`) |
| `ВыпускающееПодразделение.createУчебныйПлан()` | форма списка/кнопка «Создать план» | **ЛР3** + **ЛР4** (кнопка «Заполнить из плана прошлого года») |
| `…отправитьПланНаПроверку(план)` | команда формы документа `УчебныйПлан` | **ЛР4** (кнопка «Отправить на проверку» → статус + запись в `ИсторияСтатусов`) |
| `…подготовитьСлужебнуюЗаписку()` / `…отправитьСлужебнуюЗаписку()` / `…запроситьСтатусОбработки()` | документ `СлужебнаяЗаписка` | **ЛР4** (кнопка создания записки из плана + отбор по статусу в форме списка) |
| `СотрудникАНОК.проверитьПланНаФГОС()` | документ `ПроверкаФГОС` | ЛР2 · **ЛР5** (`ОбработкаПроведения` → `РезультатыПроверокФГОС`) |
| `…внестиИзмененияВПлан()` / `…проверитьИзмененныйПлан()` | проведение `СлужебнойЗаписки` + повторная `ПроверкаФГОС` | **ЛР5** |
| `…зафиксироватьРезультатПроверки()` | регистр сведений `РезультатыПроверокФГОС` | **ЛР5** |
| `…сформироватьЗаключение()` | отчёт `СоответствиеФГОС`, печатная форма | **ЛР7** |
| Утверждение ректором / учёный совет | документ `УтверждениеУчебногоПлана` | ЛР2 · **ЛР5** |
| — | отчёты `УчебныйПланПоПрограмме`, `НагрузкаКафедр`, `СлужебныеЗаписки` | **ЛР7** (два — обязательно, остальные — резерв) |

### ЛР3. «Введение в формы»

> «Вам предлагается для своего варианта определить три формы элемента (документа) для справочников и документов. В каждой из форм: должны быть изменены свойства как минимум 3-ёх элементов (чтобы были видны изменения); должен быть изменён порядок элементов по умолчанию; некоторые элементы должны быть сгруппированы; должны быть определены собственные реквизиты формы, а также смочь объяснить их назначение. Определить две формы списка, в каждой из которых изменить порядок или наличие колонок. А также быть готовым к вопросам по теории.»

Формулировка «для справочников и документов» означает: **3 формы элемента/документа в сумме**, и среди них должны быть и справочник, и документ.

- [ ] 3 формы элемента (документа): `ОбразовательныеПрограммы.ФормаЭлемента`, `УчебныйПлан.ФормаДокумента`, `СлужебнаяЗаписка.ФормаДокумента`.
- [ ] В каждой: ≥3 изменённых свойства элементов (видимость, заголовок, ТолькоПросмотр, цвет фона, высота, `РазрешитьИзменениеСтруктуры` и т. п.).

## 4. План действий

### 4.1 Порядок выполнения и зависимости

```
ЛР1 (проект структуры) ──► ЛР2 (объекты + данные)
                                   │
                 ┌─────────────────┼──────────────────┐
                 ▼                 ▼                   ▼
        ЛР3 (формы)         ЛР6 (Excel →        ЛР5-подготовка:
                 │          справочники)         регистраторы/движения
                 ▼                                  │
        ЛР4 (обработчики форм)                       ▼
                 │                            ЛР5 (модули объектов
                 └───────────► данные в ────────► + движения)
                                регистрах                  │
                                                           ▼
                                                   ЛР7 (СКД-отчёты)
```

Почему именно так:

* **ЛР6 не зависит** от форм и кода — можно делать параллельно/раньше, но practically после ЛР2 (нужны справочники). Единственная тонкость: справочник `Дисциплины` и `Студенты` заполняются и из ЛР2 (3–5 записей) и из Excel (7/6 строк) — дубли недопустимы, отсюда режим «обновлять существующие».
* **ЛР4 требует ЛР3** — обработчики вешаются на элементы собственных форм, без них форм нет.
* **ЛР7 требует ЛР5** — иначе регистры накопления/сведений частично пусты и отчёты выглядят бедно; плюс в отчётах мы показываем историю статусов и результаты проверок, которые документально наполняются только после ЛР5.
* Регистры накопления нельзя наполнить «вручную» — только проведением (это наш ответ на вопрос преподавателя в ЛР2).

**Убрать колонки:** `Ссылка`, `Ответственный`, `Проведён` — оставить `Проведён` только как индикатор (флажок, заголовок «Пров.»).

### 5.4 ЛР6 — внешняя обработка загрузки из Excel

#### Файлы Excel (готовы в репозитории — `data/ЛР6/`)

| Файл | Лист | Колонки (1-я строка — заголовки) | Строк |
|---|---|---|---|
| `Дисциплины.xlsx` | `Дисциплины` | `Наименование`, `КодДисциплины` | 7 |
| `Студенты.xlsx` | `Студенты` | `Наименование`, `НомерСтуденческого`, `Курс`, `Группа`, `ОбразовательнаяПрограмма` | 6 |

Требования к заголовкам соблюдены: **одно слово, без пробелов, каждое слово с большой буквы** — именно так построитель запроса назовёт поля результата («как в файле Excel, но без пробелов, и каждое слово с большой буквы»). Для `Студенты` колонка `ОбразовательнаяПрограмма` содержит **наименование** справочника — это и есть случай, требующий `НайтиПоНаименованию()`.

#### Структура внешней обработки `ЗагрузкаИзExcel_В15`

```
ВнешниеОбработки
└─ ЗагрузкаИзExcel_В15
   ├─ Форма: "Форма" (основная)
   │  ├─ Реквизиты: ПутьКФайлу (Строка), РежимОбновления (Булево),
   │  │             ТаблицаДисциплины (ТаблицаЗначений: Наименование, КодДисциплины),
   │  │             ТаблицаСтуденты (ТаблицаЗначений: Наименование, НомерСтуденческого,
   │  │                                   Курс, Группа, ОбразовательнаяПрограмма),
   │  │             РезультатЗагрузки (Строка)
   │  ├─ Команды:  ЗагрузитьДисциплины, ЗагрузитьСтуденты
   │  └─ Элементы: поле ПутьКФайлу + кнопка «Обзор…», флажок «Обновлять существующие»,
   │               2 кнопки команд (подписи «Загрузить дисциплины», «Загрузить студентов»),
   │               2 поля таблицы + поле «Результат» (многострочное)
   └─ Модуль объекта: экспортные функции (опционально)
```

#### Логика (по методичке, но **в справочники**, а не в таблицу значений)

1. **Клиент** (`&НаКлиенте`) `ЗагрузитьДисциплины()`: `ИмяФайла = ПолучитьИмяФайла("*.xlsx;*.xls")`; если пусто — выход; вызвать серверную `ПодготовитьТаблицуНаСервере()` → показать превью в `ТаблицаДисциплины`.
2. **Сервер**: `ТабДок = Новый ТабличныйДокумент; ТабДок.Прочитать(ИмяФайла);` → определить область (`ОбластьТаб = ТабДок.Область(1, 1, ТабДок.ВысотаТаблицы, ТабДок.ШиринаТаблицы);`) → собрать `ТаблицуЗначений` с колонками и типами (вариант методички №2). *Альтернатива — вариант №1 (рекомендуемый методичкой): `ПостроительЗапроса` с источником `ФайлXLSX`, `ИмяФайла`, `ПоместитьРезультатВ = ТаблицаЗначений`, далее `Построитель.Выполнить()` и выгрузка результата; точные имена свойств смотреть на скриншотах методички, раздел «Работа с MS Excel через построитель» — в разных редакциях платформы они слегка различаются.*
3. **Сервер, запись в справочник** — для каждой строки:

```bsl
СправОб = Справочники.Дисциплины.НайтиПоНаименованию(Стр.Наименование);
Если СправОб.Пустая() Тогда
    СправОб = Справочники.Дисциплины.СоздатьЭлемент();
    СправОб.Наименование = Стр.Наименование;
    Новый_Или_Обновленный = "создан";
ИначеЕсли НЕ РежимОбновления Тогда
    Продолжить; // такая запись уже есть — не создаём дубль
Иначе
    Новый_Или_Обновленный = "обновлён";
КонецЕсли;
СправОб.КодДисциплины = Стр.КодДисциплины;
СправОб.Записать();
```

4. Для `Студенты` — кросс-ссылка и приводы типов:

```bsl
СсылкаНаПрограмму = Справочники.ОбразовательныеПрограммы.НайтиПоНаименованию(Стр.ОбразовательнаяПрограмма);
Если СсылкаНаПрограмму.Пустая() Тогда
    СтрРезультата = "пропущен: нет программы «" + Стр.ОбразовательнаяПрограмма + "»";
Иначе
    Студент.ОбразовательнаяПрограмма = СсылкаНаПрограмму;
    Студент.Курс = Число(Стр.Курс); // в Excel значение может прилететь строкой
    // Перечисление ФормаОбучения — из строки Excel через helper (см. ниже), колонку в файл не кладём
КонецЕсли;
```

Приведение значения перечисления из строки (если захотим грузить и `ФормаОбучения`) — безопасный способ без `ЗначениеИзСтроки`:

## 7. Шпаргалка защиты: вопросы и готовые ответы

**Про структуру (ЛР1/ЛР2).**
1. *Почему `УчебныйПлан` — документ, а не справочник?* Есть дата, номер и жизненный цикл; справочник отвечает «кто есть кто», документ — «что и когда произошло».
2. *Почему семестр/часы/аттестация в ТЧ, а не в `Дисциплинах`?* Это свойства связи «план–дисциплина»: одна дисциплина в бакалавриате и магистратуре имеет разные часы.
3. *Почему подразделения — один справочник?* Одинаковый состав, различие — в `ТипПодразделения`; проще сопровождать.
4. *Зачем регистр сведений, если статус есть в документе?* Документ хранит текущий статус, регистр — историю «кто/когда/какой», нужно для аудита подписей.
5. *Зачем регистры накопления?* Числовые итоги считаются при проведении, отчёты строятся без пересчёта документов.
6. *Почему изменения — документом, а не правкой плана?* Требуется согласование (2 подписи), внесение АНОК и повторная проверка — событие с датой и номером.
7. *Константа vs перечисление vs справочник?* Одна ячейка / неизменяемый разработчиком список / изменяемый пользователем список.
8. *Что делает F7?* Превращает «чертёж» конфигурации в реальные таблицы ИБ.
9. *Почему регистры накопления пустые на этапе ЛР2?* Они подчинены регистраторам и заполняются только кодом проведения (ЛР5).

**Про формы (ЛР3).**
10. *Чем реквизит формы отличается от элемента?* Реквизит — данные, элемент — способ вывода; связь через `ПутьКДанным`.
11. *Почему собственный реквизит «сбрасывается»?* Данные реквизитов формы живут, пока живёт форма, и не сохраняются в БД; значения задаём при создании/в обработчиках.
12. *Зачем вам `ВсегоЧасов`/`ВсегоЗЕТ`, если есть итоги СКД и Итоги таблицы?* Это поле формы для мгновенного отображения и для проверки при записи; в БД не дублируется.

**Про события (ЛР4).**
13. *Чем `ПриСозданииНаСервере` отличается от `ПриОткрытии`?* Первое — на сервере, задаёт параметры/структуру создаваемой формы; второе — на клиенте, настраивает отображение дочерних элементов.
14. *Почему `Отказ` в `ПередЗаписьюНаСервере`?* Это точка «последнего китайского предупреждения» перед сохранением: `Отказ = Истина` отменяет запись.
15. *Зачем в `НачалоВыбора` `СтандартнаяОбработка = Ложь`?* Иначе платформа сама откроет полный список, и наш отбор/`СписокВыбора` не применится.
16. *Почему `Итог()` по таблице — это клиент?* Данные таблицы формы уже на клиенте, сервер дёргать незачем; запросы — только на сервере.

**Про модули объектов и регистры (ЛР5).**
17. *Чем запись из модуля объекта отличается от модуля формы?* Модуль формы — только интерактивная запись через эту форму; модуль объекта отрабатывает **при любой** записи, включая программную.
18. *Что дал конструктор движений и что дописали руками?* Сгенерировал `Движения.<регистр>.Заполнить(Ссылка)` и привязку полей; дописали расход старых часов и корректировки по служебным запискам, а также `МенеджерЗаписи` для регистров сведений.
19. *Почему независимый регистр, а не подчинённый?* Чтобы сохранились ручные записи из ЛР2 и не ломать структуру при переводе режима; автозапись это не отменяет (решение Р-1).
20. *Как избежать рекурсии при выставлении статуса плана из документа утверждения?* Проверка «статус уже нужен?» перед `Записать()`, и запись режима Проведение только при изменении.

**Про Excel (ЛР6).**
21. *Почему внешняя обработка, а не обычная?* Задание требует `Внешнюю обработку`; плюс её можно открывать без изменения конфигурации — реальный приём в типовой эксплуатации.
22. *Как не наделать дублей при повторной загрузке?* `НайтиПоНаименованию()` → если найден, обновить или пропустить (флажок режима).
23. *Почему имена полей результата построителя такие «кривые»?* Построитель называет колонки по заголовкам листа Excel: без пробелов, с большой буквы — поэтому заголовки и делали однословными.

**Про СКД (ЛР7).**
24. *Почему итоги не в запросе?* Использование итогов в запросе-источнике СКД недопустимо — схема может включать несколько разнотипных наборов; итоги считаются ресурсами.
25. *Как сделать, чтобы отчёт не падал без параметра?* Значение по умолчанию + пользовательская настройка + защитное условие `ИЛИ &Параметр = …` в запросе (три места, все обязательны).
26. *Можно ли в вычисляемом поле сослаться на другое вычисляемое?* Нет — ограничение СКД; обходим через дублирование выражения или через ресурсы.
27. *Что делает «Рассчитывать по»?* Ограничивает расчёт ресурса указанными группировками (и вложенными); без него — по всем, включая общий итог.

## 8. Риски и как их снять

| Риск | Вероятность | Снятие |
|---|---|---|
| База «поехала» после серии изменений метаданных | высокая | `.dt` на каждом этапе (после ЛР2, ЛР3, ЛР5…); никогда не редактировать конфигурацию в 2 окнах |
| Забыли F7 → «в Предприятии ничего не поменялось» | высокая | правило: любое изменение → Ctrl+S → F7 |
| Конфигуратор ругается: «тип реквизита не выбран», «циклическая ссылка» | средняя | порядок этапов ЛР2 (перекрёстные реквизиты в два прохода — Этап 5.3) |
| Форма списка документа пустая | средняя | задать `Запрос`/`ПараметрыДинамическогоСписка`, либо убрать отбор «Только проведенные» |
| Обработчик «не срабатывает» | средняя | проверить: событие указано в свойствах элемента, имя процедуры совпадает, метод помечен `&НаКлиенте/&НаСервере`, форма не «стандартная» (нужна сгенерированная и сохранённая) |
| Запрос на клиенте → ошибка компиляции | средняя | все `Новый Запрос` — только в `&НаСервере`/`&НаСервереБезКонтекста` |
| Дубли при загрузке из Excel | средняя | `НайтиПоНаименованию` + режим обновления (флажок) |
| Excel: колонка «Курс» прилетает строкой | средняя | `Число()` + проверка, либо числовой формат в файле (в `Студенты.xlsx` числа уже числовые) |
| Путь к файлу `.xlsx` в коде захардкожен | средняя | поле `ПутьКФайлу` + `ПолучитьИмяФайла()` |
| Отчёт падает: «не задано значение параметра» | средняя | правило трёх мест (см. вопрос 25) — прогнать отчёт с пустыми параметрами **до** демонстрации |
| Регистры накопления пусты после ЛР5 | средняя | проверить галочки регистраторов + вызов `Движения…Заполнить()` + `Отказ` не выставлен; провести документ заново |
| Учебная версия: нет COM, внешние соединения ограничены | высокая | способ №3 из ЛР6 не используем; об этом говорим прямо |
| Методички расходятся в нумерации (ЛР5 подписана «ЛР4») | высокая | в отчётах указываем и номер курса, и название методички (см. §0) |
| Не хватило объёма по «≥3 отчёта» содержательно | низкая | 4 заготовки → 2 полных по ЛР7 + резерв `НагрузкаКафедр` + `СлужебныеЗаписки` (простой отбор по статусу) |

```
1C/

├── .gitignore
├── ЛР1 2023.pdf … Практикум 1С 2023 - ЛР 7.pdf, UML(4)-ДК.drawio.pdf   ← методички и UML (источники требований)

├── data/ЛР6/
│   ├── Дисциплины.xlsx                        ← заготовки для ЛР6 (7 строк)
│   └── Студенты.xlsx                          ← заготовки для ЛР6 (6 строк, кросс-ссылка на программу)
├── docs/                                      ← сюда: ЛР3_Формы.md, ЛР4_Обработчики.md, ЛР5_Модули_объектов.md,
│                                                 ЛР6_Загрузка_Excel.md, ЛР7_Отчеты_СКД.md (+ скриншоты)
├── src/                                       ← сюда: листинги .bsl модулей форм/объектов и внешней обработки
└── backup/                                    ← .dt-копии (в git не попадают)
```

**Ближайшие 3 шага:**

1. Довести ЛР2 в живой базе (Этапы 0–13) → `.dt` → коммит. *Пока ЛР2 не выполнена в Конфигураторе, ЛР3–ЛР5 делать не на что.*
2. ЛР3 по §5.1 (5 форм), зафиксировать скриншоты в `docs/ЛР3_Формы.md`.
3. ЛР4 по §5.2 — 18 обработчиков; листинги сразу складывать в `src/ЛР4/` (чтобы `.bsl` были источником истины, а не скриншоты).

**Что сделать немедленно после ЛР5 (пока не забыто):** перенести все листинги в `src/` и добавить в README блок «код = N модулей, M строк». Если решим вести выгрузку конфигурации в XML (`Конфигуратор → Конфигурация → Выгрузить конфигурацию в XML-файлы` в `export/config/`), она станет точным доказательством соответствия структуры проекту ЛР1 — но каталог большой, в git кладём по желанию.
